# Module detail (`modules/`)

Long-form version of the core module map: behaviour, limits and the reasons behind them. Quest and trade specifics live in `quests.md` and `trades.md`.

| Module | Responsibility |
|--------|---------------|
| `config.py` | Single `Config` class reading all env vars via `dotenv`. Source of truth for all settings. `load_dotenv()` fills only unset keys, and the test suite sets `PYTHON_DOTENV_DISABLED` after explicit pre-pinning (see `conventions.md`), so production-`.env` discovery stays disabled under `pytest`. `SHINY_ALERT_USER_IDS` defaults to `[MY_ID]`; only those pilot users ever get shiny DMs. |
| `database_connector.py` | `DatabaseConnector(database?)` — pymysql wrapper returning `list[dict]` from `cursor.description`. Default DB = `Config.DB_POLISWAG`; scanner DB passed explicitly. Module-level `connect(database, read_timeout=5, dict_rows=False, **extra)` is the one way to open a short-lived connection (all `pogoleiria` readers use it) — bounded timeouts, caller closes. Conservative recovery, no SQL classification: bounded reconnect-and-retry is allowed **only before `cursor.execute` begins** (a `ping(reconnect=True)` or cursor-creation failure means nothing reached the server; retryable errnos are `2006`/`2013` plus `2003` from a failed internal reconnect, bounded by `retries`). Once execution starts there is **no replay** for either API, even reads — an arbitrary `CALL`/`WITH` can write and a `2006`/`2013` after execute or during commit leaves the outcome uncertain. The failure rolls back best-effort (never masking the caller) and raises the original error; only a failed rollback or a lost-connection (`2006`/`2013`) error refreshes/invalidates the handle for the next caller (a syntax-error rollback succeeds without refresh). `execute_transaction` never replays an uncertain commit; the next scheduler tick reconciles from stored state. Serialization: every call runs in a worker thread via `_run_serialized`, which holds the `asyncio.Lock` until the thread actually finishes — `asyncio.shield` keeps a cancelled waiter from releasing early, the next caller blocks until the outstanding thread is done, and cancellation still propagates to the waiter. |
| `http_client.py` | `fetch_data(endpoint_key, …)` — single shared `aiohttp.ClientSession`, reads from `Config.ENDPOINTS[key]`. In DEV (`not IS_PRODUCTION`) returns mock JSON from `mock_data/` for infra endpoints. |
| `scanner_status.py` | `ScannerStatus` — polls Dragonite (`/status`) + Rotom (`/api/status`) + Golbat DB. Renames a single `STATUS:` Discord voice channel with a combined down/expected-worker indicator in three states only (🟢 at least one worker up however thin the pool; 🔴 every worker down but the device connected; ❌ device offline or no data — no partial tier, it was pure rename-rate-limit churn) (expected counts read live from Dragonite per area, not hardcoded), fires HA webhook when scanner is fully down (15 min cooldown). Renames are budgeted locally (2 attempts / 10 min, 15 s timeout) because discord.py sleeps out a rename 429 (~600 s) inside `channel.edit()`, which used to stall the whole scheduler tick. Missing/unreachable data renders as ❌ but is excluded from the recovery-ladder trigger. Quest-scan progress counts, per registry area and on every check, both the stops with a valid quest and all stops inside the fence (`_count_area`, one query), so the total is always live: no stored per-area ceiling or recount script (migration `041` dropped the old `quest_expected_*` columns). Completion = flat count for 10 checks at ≥90% of the live total; never-stuck guards: 30 min flat below the floor accepts the ceiling, an empty fence counts as done, and an area at 0 quests for 2 h while others have quests stops blocking (all gated by scanner-alive). |
| `stack_recovery.py` / `device_manager.py` | Recovery aimed at what broke (rewritten 2026-09-28, after a recreate killed a scanner that had already self-healed). Each tick `_diagnose(all_red, workers)`: rotom-ng workers 0 → `device_manager.phone_health()` over adb (pidof `com.pokemod.aegis:mapping` + Pokémon GO, and Aegis's logcat line "running and injected", every ~5 s, stale after 120 s) → `phone` (broken) / `link` (healthy: Aegis reconnects itself) / `unreachable`; workers but every Dragonite worker down → `no_data`; Dragonite or rotom-ng not answering → `stack`. Rungs at 5 and 15 min into the episode: phone = apps then full; stack = full, full; link = wait, full; no_data/unreachable = one mod notice, never a restart. "full" = recreate dragonite+rotom-ng, 15 s, restart the phone's apps. Mod posts say down/why/how long/next; a green "back" follows any post. Aegis also keeps its own log at `/data/local/tmp/aegis.log` (root only; on 2026-09-28 it reached back ~11 h), handy after the fact since logcat only holds ~15 min. |
| `account_guard.py` | Account guard (2026-11-09), **alert-only**: each tick reads the new lines of `dragonite`, `lork`, `dragonite-level` and `lork-level` through the Docker socket (since the last read; the first tick warms up with 15 min and only alerts on newer events) and keeps 15 min of two event kinds: `problem` (Dragonite `ACCOUNT PROBLEM`, with its worker) and `authfail` (Dragonite `Error during authentication`, lork `Authentication failed`). Rules per stack (main/level): **worker** = one worker flags 3 accounts in 5 min (fake bans: 2026-11-05 20:36 Leiria_26 flagged one account every ~2.5 s as shadow banned); **fleet** = 5 flags from 3 workers in 10 min; **auth** = 20 failed logins in 15 min (normal days peak at 7 main / 15 level; 2026-11-04 hit 96). Replayed over 2026-11-02..09 these fire only on the 11-04 and 11-05 incidents. A trip DMs the owner (`notify_owner`, tag `account_guard`) what it *would* pause: the worker's area (`enabled: false`), every area, or on levelling the `LevelUp` mode's workers to 0. One DM per rule/stack/key per hour. `MODE` is the switch for pausing later; production only. |
| `scanner_manager.py` | Docker control (via `docker-py`) + `poliswag` table state (`last_scanned_date`, `scanned` flag). `is_day_change()` triggers a new scan cycle. |
| `quest_search.py` | `QuestSearch` — owns the scanner DB connection and the name maps. Quest lookup on the `pokestop` table, normalizing both scanner quest field sets. Strict liveness: production SELECTs carry `quest_expiry > UNIX_TIMESTAMP()` / `alternative_quest_expiry > UNIX_TIMESTAMP()`, and in-memory `_row_is_live` additionally drops any row whose carried expiry is missing, null, malformed or past — a row without a trusted future expiry is never live. Cached reads are gated by `_cache_usable` (1 h age **and** the stamp falls on today's Europe/Lisbon publication day). See `quests.md`. |
| `scan_areas.py` | The single source of scanned areas: reads the active `scan_area` rows (10 min cache) and their Dragonite geofences from `GET {DRAGONITE_API_URL}/v2/areas/` + `/v2/areas/{id}`, normalizing GeoJSON Polygon/MultiPolygon (holes respected) and Poracle `path`/`multipath`, and classifying points with ray casting. The last good fences are written atomically under `SCAN_AREA_CACHE` (`data/scan_areas.json`) and reloaded when Dragonite fails, so a scanner restart never empties the map. A point outside every active fence belongs to no area: `area_for` never guesses. Also provides labels, alert roles, Poracle names and the `sort_order` bit codes (`1, 2, 4, 8, 16`). Adding an area is a registry row plus its Dragonite area, never a code change. |
| `quest_exporter.py` | Writes `quests.json` / `quests-meta.json` for the PWA, skipping unchanged content. Candy (4), Mega Energy (12) and XL Candy (13) are species-specific with the website-compatible type kept exact (`candy`, `mega_energy`, `xl_candy`) and the species in the additive `pokemonId` field plus the grouping/id key (`type|#species|amount`); invalid species ids fall back to a species-less label. Each file is replaced atomically (same-directory temp file + `os.replace`, payload before metadata); the pair is not atomic — a crash between the two leaves a fresh payload with a stale meta, which the next export recovers by rewriting. A matching meta hash skips the write only when the on-disk payload is also usable (same content hash **and** `generatedAt` on today's Lisbon consumer day). See `quests.md`. |
| `event_manager.py` | Fetches events from ScrapedDuck (15 min cache). Stores/updates `event` table; deletes events that ended more than `EVENT_RETENTION_DAYS` (90) ago. Dispatches embed notifications to `CONVIVIO_CHANNEL` when events start/end, respecting `excluded_event_type`. Weekly digest on Mondays. Event change batches are marked delivered only after Discord accepts; manual `!testevent` previews never mark. See `events.md`. |
| `event_images.py` | `usable_image(url)`: HEAD-checks a card's thumbnail before posting; a 404 `-default.jpg` placeholder misfiled under an article folder falls back to `cdn.leekduck.com/assets/img/events/<file>`, other dead links are dropped, a failed check keeps the URL. |
| `event_store.py` | Thin DB wrapper for `excluded_event_type` and `event` tables. |
| `event_stats.py` | `EventStats.get_summary(event)` → stats text for an ended CD / Spotlight (species from ScrapedDuck `extra_data` icons, name as fallback) or Raid Hour/Day (the tier that grew vs. the day before, and its bosses); `None` for every other type, which then gets one line under the "Eventos que terminaram" header instead of a card. Golbat daily `*_stats` tables, ~7 days kept. |
| `trade_digest.py` / `trade_announcer.py` | Daily trade-supply post and live match posts. See `trades.md`. |
| `trade_dm.py` | Per-minute mutual-trade DMs from the site's derived wants. See `trades.md`. |
| `trade_codes.py` / `trade_player_store.py` / `membership.py` | `!pokedex` code generation/hash, `trade_player` identity writes, DM membership check. See `trades.md`. |
| `trade_stats.py` | Small aggregate reader over the shared trade tables (also feeds the 100IV health view). |
| `hundo_alerts.py` | Pokédex 100IV DMs, off by default: keeps `template=pokedex-100iv` Poracle rules in step with each opted-in collector's missing 100IV tiles; confirms each settings revision by DM. Detail: `docs/context/hundo-alerts.md`. |
| `shiny_roll.py` / `shiny_store.py` / `shiny_alerts.py` | Shiny prediction: the roll, the `shiny_link`/`shiny_alert` tables, link announcements and roll-0 alerts. Link-result DMs and the no-channel fallback DM go only to `SHINY_ALERT_USER_IDS` pilot users — anyone else's link is stamped silently, and an alert whose private channel is gone is dropped (logged) for non-pilot users. The delivered path is the player's own private channel (Poracle `discord:channel`, else the bot's plainer embed there). `SHINY_ALERTS_ENABLED=false` stops delivery (spawn alerts, link DMs, digests) and keeps the watermark advancing; channels, `!shiny` and the odds ticks keep running. See the internal shiny notes (not in this repo). |
| `shiny_odds.py` | Event shiny odds and never-shiny species, read off the scanner's own counts into `shiny_rate` / `shiny_species`. See the internal shiny notes (not in this repo). |
| `shiny_channels.py` / `shiny_events.py` / `shiny_availability.py` / `shiny_leaderboard.py` | Private shiny-channel reconciliation (approved website accounts; hidden for held/off/left), opt-in event digests gated by `SHINY_EVENT_DIGESTS_ENABLED` with the pilot list as delivery boundary, availability guards/breaker, leaderboard image. See the internal shiny notes (not in this repo) + `shiny-event-digests.md`. |
| `spawn_history.py` | Independent 48-hour raw spawn archive, compressed JSON export and unfiltered trainer statistics. See `spawn-history.md`. |
| `mega_exporter.py` | Mega sprites for the site, shrunk to ≤160px. |
| `quest_map.py` | Viewport and A–J labels for the self-hosted quest PNGs. See `quests.md`. |
| `account_monitor.py` / `account_card.py` | Polls Dragonite `/accounts/stats` and Rotom for the scanning pool and, when `SCANNER_LEVEL_ACCOUNTS_STATUS_ENDPOINT` is set, the levelling pool (dragonite-level / rotom-ng-level). Per pool: in use + ready (good + never used, `zero_last_released`) + cooldown + out (banned, auth-banned, suspended, invalid, warned, disabled, provider-disabled) = Dragonite's total; `missing_token` overlaps those buckets and is never summed (a mismatch is logged once per change). `account_card.py` builds the card's view model (bar widths, exact height, status: destructive when the scanning device is offline or nothing is ready, urgent when ready < workers). Posts the image to `ACCOUNTS_CHANNEL`; `!accounts` sends the same card. |
| `poracle_client.py` | `PoracleClient` — async REST client for Poracle-NG (`X-Poracle-Secret` header). Methods: `get_channels`, `get_pokemon`, `add_pokemon`, `create_user`, `delete_pokemon`, `set_enabled`, `register_channel`, `send_test`. Raises `PoracleError` on non-2xx. |
| `tracker_store.py` | CRUD for `tracked_quest_reward` (the `!track` family). See `quests.md`. |
| `polisnatch_api.py` / `polisnatch_store.py` / `polisnatch_jobs.py` | PoliSnatch job API: the shared contract (base URL, submit key, Bearer header, error shape; stdlib-only so the host linker uses it too), the `polisnatch_job` ledger, and the bot's async client plus `JobPoller`. The poller reads the table every 30 s when idle and only sends HTTP while rows are queued/claimed; its first tick after READY resumes whatever a previous process left open, and each outcome is announced once (editing the queued message, sending a fresh one when it is gone). Stop locks/cooldowns stay in `lure_locks.py`; link outcomes stay the shiny linker's to write. |
| `lure_manager.py` | `LureManager` — owns a read-only `DatabaseConnector(DB_DRAGONITE)`. `list_available_with_lures()` reads available+healthy accounts from `dragonite.account` (not banned/suspended/warned/invalid/auth_banned, off cooldown, `last_released >= last_selected`), seeds new usernames into `account_lure` at 12, returns up to 5 fewest-first with `{username, password, nb_lures}`. `adjust_lure_count(username, delta)` → `GREATEST(nb_lures+delta, 0)` UPDATE. Writes only `poliswag.account_lure`; dragonite is read-only. |
| `lure_watcher.py` | `LureWatcher.count_active_lures()` — `pokestop` rows with `lure_expire_timestamp > UNIX_TIMESTAMP()`, for the bot's presence line. `Scheduled._update_lure_status` skips the API call when the count is unchanged and caches the count only after `change_presence` succeeds, so a transport failure retries next tick. |
| `role_manager.py` | Handles Discord role button interactions for the **legacy** team/notification panel: resolves roles by *name*, auto-grants all `Alertas*` roles to a brand-new member, and `defer()`s with no reply. `cogs/event_panel.py` deliberately does not reuse it — see that file's header. |
| `permissions.py` / `help_command.py` / `dm_policy.py` | Three audiences (`is_mod`/`is_owner`, `mods_only()`/`owner_only()`); `!help` sections by the same gates (`_OWNER_COGS`, `cog_check`, `command.checks`) and deletes its command message. `may_run_in_dm` blocks stranger DMs; only the Pokédex (`!pokedex`/`!resumo`) and Shiny (`!shiny`) cogs are DM-exempt with their own membership checks. |
| `public_conversation.py` / `conversation_model.py` | Member-tag replies behind `cogs/mentions.py`: the sanitized question plus a validated public map snapshot (`public_map_context.py`) and locally rendered calendar/statistics facts go to Codex Luna low on a fixed topic, with strict input/output validation, `MentionLimiter` cooldowns (1 per member/15 s, 5 per guild/30 s). Non-owner conversational DMs are silent; failures fall back to honest local replies. See `agents.md`. |
| `page_view_stats.py` / `page_view_report.py` / `webstats_access.py` | Read-only landing analytics (`DB_POGOLEIRIA`) and the private `!stats` report with token-gated access. `tracking_health.py` logs traffic silence/resumption once per episode and never DMs. |
| `owner_alert.py` | `notify_owner(poliswag, text, title, tag)` — operational alerts straight to the owner's DMs; `False` when `MY_ID` is unset or delivery fails. |
| `migrations.py` | `apply_migrations(db, log)` replays every `migrations/*.sql` in filename order on each start, before cogs load; one bad statement is logged without stopping the bot. Files stay re-runnable (`IF NOT EXISTS`); no tracking table. |
| `image_generator.py` | `imgkit` + Jinja2 → PNG bytes from `accounts.html` (PoGoLeiria design tokens, rendered at 2x through CSS `zoom` and losslessly recompressed with Pillow, ~90 KB); renders quest map PNGs through Rampardos (`QUEST_MAP_URL`, `QUEST_MAP_STYLE`) — see `quests.md`. Alert reward sprites get small letter badges; sprite bytes are cached (64 rewards), with letter-only fallback on icon failure. Quest replies attach the PNG to Discord; render failures keep the text list. |

| `utility.py` | `log_to_file(msg, level)` — dual-logger (`poliswag` info + `poliswag.error`). `time_now()`. `get_new_pokemongo_version` uses a bounded 15 s `VERSION_CHECK_TIMEOUT` so a stalled Niantic check cannot hold the 60 s scheduler tick open. |

**Scanner phone recovery (2026-11-09).** The phone is PoliSnatch's (Aegis retired 2026-10-31). `DeviceManager.phone_health` reads the loader and game PIDs and the installed Pokémon GO build in one adb call: `game_updated` when the build differs from the one the phone last scanned with (`remember_working_version`, hourly while scanning, `SCANNER_GAME_VERSION_FILE`), `broken` when the loader or the game is not running. The phone rung brings the game (or, without a game, the loader) to the front with `monkey`; it never force-stops. `game_updated` gets no restart: `StackRecovery` tells the mod channel and DMs the owner once, with the cause (a Play Store update the release doesn't support). The account guard no longer blocks the phone rung when Rotom has no worker in use (87 accounts held by waiting controllers deferred it for five hours on 2026-11-09). A new forced Pokémon GO version also DMs the owner, since the phone keeps scanning until the Play Store updates it.

**Scanner notices in the mod channel (2026-11-09).** `modules/scanner_notice.py`: every scanner notice (DeviceManager and StackRecovery `_notify`) edits the channel's latest message when it is Poliswag's scanner card (footer `Estado do scanner`), else posts a new card and deletes the previous one (id in `SCANNER_CARD_FILE`); the card shows "Em baixo desde" from the first failure and closes with the downtime. Owner DMs are unchanged.
